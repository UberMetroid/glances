About glances-rs.

Background, architecture and history of the pure-standard-library Rust port of Glances.

01What is Glances?

Glances is a cross-platform system monitor written in Python by Nicolas Hennion (a.k.a. Nicolargo) and a long list of contributors. It surfaces CPU, memory, swap, load, network, disk, sensors, filesystem, processes, alerts, logs and Docker container metrics from a single curses TUI, an embedded browser UI served over HTTP, or one of two dozen remote exporters. Glances is the kind of tool you keep one terminal pane wide on every box you care about.

Python Glances is mature, popular and battle-tested. glances-rs is not a replacement — it is a reimplementation in Rust with stricter dependency guarantees.

01aCredits

glances-rs is a derivative work of Glances. All credit for the original architecture, plugin model, exporter set, and CLI surface belongs to the upstream authors, in particular:

  • Nicolas Hennion <nicolashennion@gmail.com> — creator and lead maintainer of Glances, known online as Nicolargo.
  • The hundreds of contributors to nicolargo/glances who shaped the plugin protocol, the REST API, the XML-RPC surface, and every exporter target that glances-rs ports.

The Rust port preserves the LGPL-3.0 license terms and the upstream attribution in every file that descends from a Python original. See the AUTHORS history in upstream Glances for the full contributor list.

02Why a Rust port?

Python Glances has a healthy runtime footprint — an interpreter, a web framework, an XML-RPC stack, a dozen exporter libraries, plugin discovery via filesystem walks. That is a lot of moving parts to install on a minimal container image, and a lot of transitive supply-chain to audit when a CVE lands.

Rust lets us keep the same architectural surface area — plugins, exporters, REST API, server, CLI — while collapsing the entire dependency graph to a handful of libc calls. The binary that comes out of cargo build --release is a single stripped executable with no libpython, no site-packages, no pip, and no .cargo/registry.

03Architecture

The crate is std-only: no [dependencies] in Cargo.toml, no extern crate statements, no third-party build scripts. The crate surface is split into:

  • core/ — Value, Plugin trait, Stats, History, Threshold, Timer, Logger, Error, Filter.
  • cli/ — hand-written argument parser; no clap.
  • platform/linux/ — the only platform layer, gated to Linux; the only place unsafe is allowed. macOS and Windows support was removed in v0.9.0 because the maintainer has no hardware to test FFI on.
  • plugins/ — one file per plugin (31 registered).
  • outputs/, exports/, server/ — stdout writers, network exporters, HTTP server.
  • qa/ — test harness: unit, integration, edge and lint suites.

Layout at a glance:

glances-rs/
├── Cargo.toml         no [dependencies]
├── src/
│   ├── main.rs        CLI dispatch; binary entry
│   ├── lib.rs         re-exports for integration tests
│   ├── cli/           hand-written parser
│   ├── core/          Value, Plugin, Stats, ...
│   ├── platform/
│   │   └── linux/     /proc + /sys readers (pure std, Linux-only)
│   ├── plugins/       one file per plugin (31 registered)
│   ├── outputs/       stdout CSV / JSON / api_doc
│   ├── exports/       18 network exporters
│   ├── server/        HTTP/1.1 + SSE + auth
│   └── qa/            tests + lint
└── qa/
    ├── lint/          no_crates, line_cap, unsafe_allowlist, no_shell
    ├── unit/          per-module tests
    ├── integration/   end-to-end smoke
    ├── edge/          malformed inputs, panic isolation
    └── fixtures/      sample /proc + /sys captures

Three hard constraints are enforced by lint, not by convention:

  • No file > 256 lines. Forces the same decomposition the original Python code does.
  • No unsafe outside src/platform/.
  • No shell expansion — every subprocess is a std::process::Command with explicit argv.

04Tested on

Linux x86_64 (primary) Linux aarch64

Linux x86_64 is the primary target: /proc and /sys readers are implemented and exercised by integration tests against a live host. Linux aarch64 is the secondary target (same code paths; tested on Raspberry Pi 4 / 5). macOS and Windows support was removed in v0.9.0 because the maintainer does not have hardware to test FFI on. The build refuses non-Linux targets with a compile_error! assertion.

05Project history

  • v0.1.0 Repo skeleton, CLI parser skeleton, and the full core type surface (Value, Plugin, Stats, History, Threshold, Timer, Logger, Error, Filter).
  • v0.2.0 Config + Args + password file loading from disk and the full CLI flag set, matching upstream Glances.
  • v0.3.0 Linux platform primitives: /proc/stat, /proc/meminfo, /proc/loadavg, /proc/uptime, /proc/net/dev, /proc/diskstats, /sys/class/net, /sys/class/hwmon.
  • v0.4.0 macOS and Windows platform stubs (later removed in v0.9.0), plus the 7 core plugins (cpu, mem, memswap, load, uptime, now, system) reading live /proc.
  • v0.5.0 stdout CSV / JSON / api_doc outputs and the HTTP server scaffolding: REST API, auth, SSE.
  • v0.6.0 24 plugins total, 18 exporters (CSV, JSON, InfluxDB v1/v2, statsd, Prometheus, RESTful, Cassandra, ClickHouse, CouchDB, Elasticsearch, Kafka, MongoDB, MQTT, NATS, OpenTSDB, RabbitMQ, Riemann), and the XML-RPC server scaffolding.
  • v0.7.0 XML-RPC server endpoint (/RPC2), Model Context Protocol (MCP) JSON-RPC 2.0 interface for AI assistants, embedded web templates (index, about, browser), and removal of the legacy Python codebase (glances-py).
  • v0.8.0 Repository restructuring: flattened rust-port/ directly into the repository root, purged all Python-era test suites and artifacts, and added official LGPL-3.0-only license.
  • v0.8.1 Studio2201 CI workflows (aegis, boneyard, proven, snip, vigil), automated install.sh deployment script, README overhaul, and upstream contributor credits.
  • v0.8.2 Self-verifying install.sh in repo root with companion install.sh.sha256 integrity checksum, and streamlined one-liner installation documentation.
  • v0.9.0 Dropped macOS Mach and Windows Win32 platform stubs to focus strictly on a zero-dependency, pure-standard-library Linux implementation (32 plugins, 18 exporters) with compile-time target assertions.
  • v0.9.1 Updated project history and documentation across the embedded web templates and GitHub Pages site.
  • v0.10.0 Full-repo audit remediation: statvfs FFI ABI fix, delta-based CPU/per-CPU percentages, wire-protocol corrections (XML-RPC, MCP, MQTT, NATS, Riemann), a strict JSON parser and regex engine, live refresh loops for server modes, exporter dispatch for all 18 targets, and complete CLI flag wiring.
  • v0.10.1 Zero-trust audit remediation wave 2: meminfo KiB-to-bytes and psutil-compatible used/free formulas, CPU guest/total parity, live disk/filesystem/network parsing fixes, InfluxDB v3 exporter (19 exporters total), real CQL/AMQP/OP_MSG exporter handshakes, lock-poisoning recovery, and per-plugin limit wiring for all 31 plugins.
  • v0.10.2 Audit follow-ups: fixed a /proc/net parser panic on short non-combined lines, MCP string request ids now round-trip instead of returning null, consistent lock-poisoning recovery in the Prometheus exporter, hardened the process-filter memo key, and synced README/site (branch rust is now the default).
  • v0.10.3 Toolchain update (MSRV 1.98.1), removed dead verify_constant_time auth helper, and started the 1:1 upstream-parity pass against Python Glances.
  • v0.10.4 Rust edition 2024, full plugin parity (35): new processlist (/proc per-process details), programlist (grouped by name), smart (smartctl ATA/NVMe health), and vms (virsh + Multipass) plugins with 25 new tests.
